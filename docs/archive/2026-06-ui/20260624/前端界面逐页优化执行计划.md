# 前端界面逐页优化执行计划

## 1. 执行目标

本计划用于指导其他 AI 或开发人员基于已安装的 OpenCode 前端 skills，对当前医疗质控系统前端进行逐页设计、优化和完善。

优化范围以静态前端为主：

- `static/templates/pages/*.html`
- `static/templates/common/*.html`
- `static/styles/**/*.css`
- `static/scripts/modules/*.js`
- `static/scripts/utils/*.js`
- `static/scripts/app.js`
- `static/index.html`
- 前端静态测试文件，如 `tests/test_dashboard_frontend_static.py`

默认不修改后端接口、数据库模型、权限逻辑、调度逻辑、Dify 推送逻辑、质控业务语义。

本计划采用“渐进式前端改造”，不是推翻重做。其他 AI 执行时必须先阅读目标页面现有 HTML/CSS/JS，理解已实现能力，再做最小正确改造。

## 2. 已安装 Skills

当前已安装以下 OpenCode 全局 skills：

| Skill | 适用场景 |
|---|---|
| `medical-ui-design-system` | 全系统颜色、间距、圆角、阴影、字体、卡片、按钮、表单、状态标签、全局一致性 |
| `medical-dashboard-screen` | 首页总览、运行总览、大屏、KPI、ECharts、健康状态、运营总览 |
| `medical-table-experience` | 推送日志、患者质控、前置机告警、反馈、权限、配置列表等表格体验 |

| `medical-workflow-visualization` | 质控闭环、推送进度、AI链路、调度任务、Dify调用、前置机告警流程 |

## 3. 给其他 AI 的 Skill 调用说明

在开始设计或修改某个页面前，其他 AI 应先按页面类型加载对应 skill。

示例：优化首页大屏时：

```text
请先加载并遵循以下 skills：
- medical-ui-design-system
- medical-dashboard-screen
- medical-workflow-visualization

目标：只优化前端静态页面，不改后端接口和业务逻辑。若需要新增接口、改字段、改权限、改调度逻辑，必须先暂停并询问用户。
```

示例：优化表格页时：

```text
请先加载并遵循以下 skills：
- medical-ui-design-system
- medical-table-experience
- medical-detail-redesign

目标：优化筛选区、摘要卡、表格密度、状态标签、详情抽屉和空状态。保持现有接口参数和响应结构不变。
```

示例：优化流程页时：

```text
请先加载并遵循以下 skills：
- medical-ui-design-system
- medical-workflow-visualization

目标：展示流程状态、任务进度、失败原因和下一步操作。不得修改推送、调度、锁、重试等后端执行逻辑。
```

## 4. 必须先询问用户的情况

如果遇到以下情况，必须停止并询问用户，不允许自行决定：

- 需要新增、删除或修改后端接口。
- 需要修改数据库字段、模型、迁移逻辑。
- 需要修改 Dify 入参、输出解析、workflow 变量、JSONPath。
- 需要修改调度任务执行逻辑、锁逻辑、推送重试逻辑。
- 需要修改权限模型、角色、菜单授权逻辑。
- 需要引入新前端框架、构建工具、外部 CDN 或大型依赖。
- 需要大规模重写 `static/scripts/app.js` 的全局状态结构。
- 需要删除已有页面功能、按钮、筛选项、导出能力或详情字段。
- 设计改动会导致用户操作路径明显变化，比如把表格页改为纯卡片页。
- 需要把首页深色科技风整体替换成另一种风格。
- 需要把所有业务表格页整体切换为深色主题。
- 需要替换菜单结构、菜单分组、菜单权限或新增一级菜单。
- 需要替换当前 emoji 菜单图标为 iconfont、SVG 图标库或第三方图标依赖。
- 需要改动生产部署方式，或直接同步到生产环境。

以下情况也应先询问用户，视为“改动较大”：

- 单个页面新增超过 3 个新的 JS 方法，且不是纯展示辅助方法。
- 单个页面新增超过 120 行 CSS，或改动全局 CSS 超过 50 行。
- 同时修改超过 1 个菜单页面的模板文件。
- 修改 `static/scripts/navigation.js`、`static/scripts/app.js` 的菜单、权限或全局状态结构。
- 删除用户可见字段、按钮、筛选项、导出入口、详情入口。

可以不询问、直接执行的情况：

- 调整 CSS、布局、卡片、间距、颜色、圆角、阴影。
- 优化已有 Vue 模板结构，但不删除业务字段。
- 优化 ECharts option、tooltip、legend、空状态。
- 增加前端空状态、加载态、错误提示。
- 增加不影响接口的点击跳转或筛选联动。
- 同步更新静态测试断言和资源版本号。

## 5. 全局设计基线

所有页面应逐步统一以下规则：

| 项目 | 规则 |
|---|---|
| 视觉风格 | 医疗后台风格，可信、稳重、清晰、低噪声 |
| 主色 | 蓝色系为主，红色仅用于高危/失败，橙色用于警告/待处理，绿色用于成功/正常 |
| 卡片 | 统一圆角、边框、阴影、标题区和工具区 |
| 表格 | 高密度但可读，固定关键列，状态标签语义统一 |
| 详情 | 优先抽屉或左右分栏，突出患者、风险、证据、处理状态 |
| 流程 | 展示当前阶段、成功/失败/跳过、失败原因和下一步 |
| 响应式 | 1366px 无横向溢出，移动端自动单列 |
| 空状态 | 不出现突兀白块，说明当前无数据原因和下一步 |
| 动效 | 只用于反馈状态变化，不做过度装饰 |

建议先在 `static/styles/app.css` 或页面 CSS 内逐步沉淀变量，不强行一次性全局重构。

### 5.1 深浅色策略

当前首页已经是深色科技驾驶舱 V2。后续视觉方向明确为：

- 首页总览、运行总览、系统健康等态势类页面可以继续使用深色科技风。
- 患者质控、前置机告警、质控反馈、推送日志、权限管理等高频表格页默认保持浅色医疗后台风，不整体切深色。
- 两类页面通过统一主色、状态色、圆角、卡片标题、按钮样式、状态标签语义保持一致。
- 本阶段不做全局 dark/light 主题切换开关，除非用户明确要求。
- 禁止为追求统一而把所有页面强制改成深色，也禁止把首页 V2 直接改回普通浅色后台。

### 5.2 全局样式范围

逐页改造时，允许按需修改以下全局或组件样式，但必须控制影响面：

| 文件 | 允许改动 |
|---|---|
| `static/styles/app.css` | 全局背景、内容区、通用变量、登录页基础样式 |
| `static/styles/components/sidebar.css` | 左侧导航、菜单组、菜单项、折叠/移动端菜单 |
| `static/styles/components/header.css` | 顶部栏、健康标签、用户入口、推送指示器 |
| `static/styles/components/stat-cards.css` | 通用统计卡样式 |
| `static/styles/components/charts.css` | 通用图表容器、空状态、图表标题 |

修改全局样式时必须说明影响范围，并优先使用页面实际已有或按本节规则追加的专属根 class 限定，例如 `.page-dashboard`、`.page-feedback`、`.page-patient-qc`，避免污染其他页面。

页面根 class 必须以实际模板为准，不允许凭命名习惯猜测。当前页面根 class 现状并不统一，执行前必须检查目标模板最外层节点。

页面样式隔离规则：

- 优先复用已有页面专属根 class，例如 `.page-dashboard`、`.page-feedback`、`.page-push`、`.page-logs`。
- 若页面只有 `.page-view` 或通用 `.page-section`，允许在最外层 `<section>` 追加一个页面专属 class 作为样式隔离钩子，例如 `page-patient-qc`、`page-relay-alert`、`page-config`。
- 追加 class 不算“大改”，但不得新增额外包裹层，不得改变 `v-show` / `v-if` 条件，不得改变现有 tab 逻辑。
- 如果页面内部已经用共享 class，如 `.page-admin`，新增页面专属 class 时不得删除共享 class。
- 全局样式必须尽量写成 `.page-xxx .component` 或 `.dashboard-tech-v2 .component`，避免裸写 `.el-table`、`.page-view` 等高污染选择器。

当前已核对的页面根 class：

| 页面 | 当前根 class | 建议隔离方式 |
|---|---|---|
| 首页总览 | `.page-dashboard.dashboard-tech-v2` | 直接复用 |
| 患者质控 | `.page-section` | 可追加 `.page-patient-qc` |
| 前置机告警 | `.page-view` | 可追加 `.page-relay-alert` |
| 质控反馈 | `.page-feedback` | 直接复用 |
| 推送日志 | 外层 `.page-view`，日志 tab 为 `.page-logs` | 优先复用 `.page-logs`，必要时给外层追加 `.page-audit` |
| 手动推送 | `.page-push` | 直接复用 |
| 定时任务 | `.scheduler-page` | 直接复用，必要时追加 `.page-scheduler` |
| 推送进度 | `.page-view` | 可追加 `.page-push-progress` |
| 系统配置 | `.page-view`，多个 config tab | 可追加 `.page-config`，tab 内用专属 class 限定 |
| 审计类型 | `.page-admin` | 保留 `.page-admin`，可追加 `.page-audit-types` |
| 企业微信推送配置 | `.page-view` | 可追加 `.page-relay-config` |
| 系统健康 | `.page-view` | 可追加 `.page-health` |
| Dify 调试 | `.page-view` | 可追加 `.page-debug` |
| 权限管理 | 外层 `.page-view`，内部 `.page-admin` | 保留 `.page-admin`，可追加 `.page-access` |
| Oracle 连接 | `.page-view` in `placeholder.html` | 可追加 `.page-oracle-status` |
| 运行日志 | `.page-view` in `placeholder.html` | 可追加 `.page-system-logs` |

`static/scripts/utils/*` 修改边界：

- 允许在不改变导出函数签名和返回语义的前提下优化状态标签、格式化文案、空值显示。
- 删除导出函数、改函数名、改参数含义、改变状态值映射，必须先询问用户。

`static/templates/common/overlays.html` 修改边界：

- 仅当详情弹窗、抽屉、全局 overlay 结构确实位于该文件时才修改。
- 修改前必须确认哪些页面复用该 overlay。
- 不得为了单页效果破坏全局弹窗、详情、复制、关闭等现有交互。

### 5.3 登录页和菜单图标

- 登录页纳入整体视觉统一，但不作为第一阶段必做。建议在首页 V3 验收后，作为“全局壳层优化”处理。
- 登录页应与系统品牌统一，可保留当前浅色安全登录风格，但需要与侧边栏、首页主色一致。
- 当前菜单图标使用 emoji。第一轮前端优化不替换图标库，只允许调整 emoji 的尺寸、间距、背景和对齐。
- 如需替换为 SVG/iconfont/Element Plus icons，必须先询问用户。

### 5.4 版本号命名规则

修改静态资源后，应同步更新 `static/index.html` 或 `static/scripts/app.js` 中对应资源版本号。

统一格式：

```text
v=YYYYMMDD-{page}-{phase}
```

示例：

```text
v=20260628-dashboard-v3
v=20260628-patient-qc-v1
v=20260628-relay-alert-v1
```

规则：

- 同一轮页面改造使用同一后缀。
- 不要混用 `u1`、`tech-v2`、`phase3` 等旧式命名。
- 只更新本轮实际改动文件的引用版本号。

### 5.5 测试失败处理原则

- 如果测试失败暴露真实功能或 DOM 缺失，应优先修代码。
- 如果测试断言仍在检查旧视觉结构、旧 class、旧版本号，可更新测试。
- 不允许为了通过测试删除对关键功能的断言。
- 更新测试时必须说明“旧断言为何不再适用，新断言验证什么”。

### 5.6 多 AI 协作规则

- 每轮只处理一个菜单页面。
- 不允许多个 AI 同时修改 `static/index.html`、`static/styles/app.css`、`static/scripts/app.js`。
- 每页完成后先跑测试并让用户确认，再进入下一页。
- 如需提交 Git，由用户明确要求后再执行；提交前必须检查 `git status` 和 diff。

## 7. 第一阶段：首页总览大屏 V3 执行计划

### 7.1 加载 skills

执行前加载：

- `medical-ui-design-system`
- `medical-dashboard-screen`
- `medical-workflow-visualization`

### 7.2 修改范围

优先修改：

- `static/templates/pages/dashboard.html`
- `static/styles/pages/dashboard.css`
- `static/scripts/modules/dashboard.js`
- `static/index.html`
- `tests/test_dashboard_frontend_static.py`

### 7.3 首页目标

首页首屏必须直接回答：

- 今日系统是否正常？
- 今日质控量、异常量、高危量、待处理量是多少？
- 风险集中在哪些科室和维度？
- 推送、告警、医生查看、反馈闭环有没有卡点？
- 用户下一步应该点击哪里处理？

### 7.3.1 V2 到 V3 的继承关系

首页 V3 必须基于当前深色科技驾驶舱 V2 精修，不允许推翻重做。

保留内容：

- 深色科技主风格和 `.dashboard-tech-v2` 页面隔离根 class。
