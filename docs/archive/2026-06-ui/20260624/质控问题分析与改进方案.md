## P1：progress_vs_nursing risk_score=0【非 Bug，系统设计如此】

### 复核结论：正常运行，不需要修改

### 完整代码追踪

**第一层：AI 返回 hcjg**

Dify workflow 对 progress_vs_nursing 返回的 JSON 中：
```json
{
  "audit_summary": {
    "risk_score": 0,     // ← AI 没有给 risk_score，默认 0
    "severity": "high"   // ← AI 正确给出了 severity
  },
  "dimensions": [...]
}
```

AI 不返回 risk_score 是**正常的**——prompt 要求 AI 判断维度 status/severity，但不要求 AI 自己算总分。

**第二层：parser 解析**（`dify_schema_parser.py:85`）

```python
result["risk_score"] = _safe_int(summary.get("risk_score", summary.get("风险分值", 0)))
# 从 hcjg.audit_summary.risk_score 读取 → 得到 0
```

**第三层：后处理回退计算**（`dify_schema_parser.py:374-375`）

```python
if not result.get("risk_score"):
    result["risk_score"] = _risk_score_from_dimensions(result["dimensions"], result.get("inconsistency", False))
```

这里 `not 0` 为 True，触发回退计算。

**第四层：维度加权**（`dify_result_normalizer.py:129-140`）

```python
def risk_score_from_dimensions(dimensions, inconsistency):
    score = 0
    for dim in dimensions:
        if dim.get("status") == "fail":   score += 25
        elif dim.get("status") == "warn": score += 15
        elif dim.get("status") == "pass": score += 2
    return min(score, 100)
```

验证：
- ID=80006：1 个 fail + 5 个 pass = 25 + 10 = **35** ✅ 与 DB 一致
- ID=91129：2 个 fail + 4 个 pass = 50 + 8 = **58** ✅ 与 DB 一致
- ID=101568：2 个 warn + 4 个 pass = 30 + 8 = **38** ✅ 与 DB 一致

### 结论

**这不是 Bug。** 系统的完整链路是：
1. AI 返回维度级别判断（status/severity）
2. AI 的 `audit_summary.risk_score` 默认为 0（因为 prompt 不要求 AI 算总分）
3. parser 的后处理逻辑 `_risk_score_from_dimensions` 根据维度 status 加权计算出 risk_score
4. DB 存储的是**计算后的 risk_score**（35-58），不是 AI 原始返回的 0

**severity=high 的来源**：AI 正确返回了 `audit_summary.severity = "high"`，parser 直接读取，不经过回退计算。

### 可选优化（非必须）

如果希望 AI 也直接返回 risk_score（减少对回退逻辑的依赖），可以在 Dify workflow 的 prompt 中增加要求："请根据维度严重程度给出 0-100 的风险分值"。但这属于 prompt 优化，非 Bug 修复。

## P2：HCJG_BAD — hcjg 为空字符串【需增加容错】

### 复核结论：Dify End 节点输出为空，非 parser 问题

### 根因分析

**证据**：10 条 HCJG_BAD 的 RESPONSE_JSON 内容为：
```json
{"hcjg": ""}
```

这意味着 Dify workflow 的 End 节点输出了空字符串。可能原因：
1. **Dify workflow 版本变更**：这 10 条记录的 PUSH_TIME 在 workflow 更新前，End 节点输出变量名或格式不同
2. **Dify 执行超时或异常**：workflow 运行成功（HTTP 200）但 End 节点未输出内容
3. **输入数据问题**：mr_text 为空或格式异常导致 workflow 无法生成结论

**parser 当前处理**：`dify_pusher.py:222`
```python
parsed = parse_dify_structured_output(outputs, output_key)
# output_key = "hcjg"，outputs["hcjg"] = ""
# → 解析空字符串 → parsed 为空 → 后处理回退 → risk_score=0, severity=""
```

当 hcjg 为空时，parser 的 `_post_process_result` 会尝试回退，但因为没有 dimensions 数据，最终结果是 risk_score=0。然而 DB 中这些记录的 RISK_SCORE=90——这说明**有另一个来源设置了 risk_score**。

检查 `dify_pusher.py:242`：
```python
"risk_score": parsed.get("risk_score", 0),
```

如果 parsed 为空，这里得到 0。但 DB 记录是 90。这意味着 RISK_SCORE=90 可能来自：
- 手动审核覆盖
- 或 parser 的某条回退路径计算出了 90

**需要进一步确认**：这 10 条记录的 PARSE_STATUS 值。

### 改进方案

**方案 1：增加空 hcjg 的检测日志**

在 `dify_pusher.py` 的解析逻辑后增加检查：

```python
# dify_pusher.py，在 parsed = parse_dify_structured_output(...) 之后
if not str(outputs.get(output_key, "")).strip():
    audit_logger.warning(
        "[Dify空输出] patient_id=%s, output_key=%s, workflow_run_id=%s, "
        "outputs_keys=%s, elapsed_ms=%s",
        patient_id, output_key, data.get("workflow_run_id", ""),
        list(outputs.keys()) if isinstance(outputs, dict) else "N/A",
        elapsed,
    )
```

**方案 2：STATUS 标记为 "parse_failed" 而非 "success"**

当前 hcjg 为空时 STATUS 仍为 success。应该在 parser 检测到空输出时标记：

```python
# dify_schema_parser.py，在 parse_dify_structured_output 入口处
raw_text = str(outputs.get(output_key, "") or "").strip()
if not raw_text:
    result["parse_error"] = f"Dify End 节点输出变量 '{output_key}' 为空"
    result["parse_success"] = False
    _append_parse_warning(result, "empty_output")
    return result
```

### 影响评估
- 影响范围：仅 10 条历史记录（67000-69000 ID 段）
- 新增逻辑不影响正常记录（有内容的 hcjg 不受影响）
- 不需要回填历史数据（旧记录保持原样）

## P3：jyjc_vs_bcnursing 逐日列表噪声【确认问题，需改进】

### 复核结论：确认问题成立，建议修改

### 根因定位

**文件**：`app/services/lab_exam_payload_builder.py:636-689`

**函数**：`_build_discharge_day_groups(bundle)`

```python
def _build_discharge_day_groups(bundle):
    sources = getattr(bundle, "sources", {}) or {}

    for rec in (sources.get("lab") or []):      # ← 遍历所有检验（含正常）
        day = normalize_date_to_ymd(rec.get("result_time"))
        day_map[day]["检验报告信息"].append({...})

    for rec in (sources.get("exam") or []):     # ← 遍历所有检查（含正常）
        day = normalize_date_to_ymd(rec.get("report_time"))
        day_map[day]["检查报告"].append({...})

    for rec in (sources.get("progress") or []):  # ← 遍历所有病程
        ...

    for rec in (sources.get("nursing") or []):   # ← 遍历所有护理
        ...
```

**问题**：对 lab 和 exam 没有做 `is_abnormal` 过滤。所有正常检验结果也写入了逐日列表，导致：
- mr_text 过大（最大 40KB，含 10 天正常+异常数据）
- AI 需要处理大量无关信息
- 增加 Dify token 消耗

### 改进方案

修改 `_build_discharge_day_groups`，对 lab/exam 只保留异常项：

```python
def _build_discharge_day_groups(bundle: PatientBundle) -> list[dict[str, Any]]:
    from collections import defaultdict

    day_map: dict[str, dict[str, list[dict[str, Any]]]] = defaultdict(
        lambda: {"检验报告信息": [], "检查报告": [], "病程记录": [], "护理记录": []}
    )

    sources = getattr(bundle, "sources", {}) or {}

    for rec in (sources.get("lab") or []):
        # 只保留异常检验
        if not _is_abnormal_truthy(rec.get("abnormal_indicator")):
            continue
        day = normalize_date_to_ymd(rec.get("result_time"))
        if day:
            day_map[day]["检验报告信息"].append({
                "检验单号": _as_text(rec.get("test_no")),
                "检验项目": _as_text(rec.get("test_name")),
                "报告项目名称": _as_text(rec.get("item_name")),
                "检验结果": _as_text(rec.get("result")),
                "异常标记": _as_text(rec.get("abnormal_indicator")),
                "结果时间": _as_text(rec.get("result_time")),
            })

    for rec in (sources.get("exam") or []):
        # 检查报告保留全部（检查报告通常数量少，且难以判断"异常"）
        day = normalize_date_to_ymd(rec.get("report_time") or rec.get("exam_time"))
        if day:
            day_map[day]["检查报告"].append({
                "检查号": _as_text(rec.get("exam_no")),
                "检查类别": _as_text(rec.get("exam_class")),
                "检查名称": _as_text(rec.get("exam_name")),
                "报告时间": _as_text(rec.get("report_time") or rec.get("exam_time")),
                "检查所见": _as_text(rec.get("description")),
            })

    # progress 和 nursing 保持不变（它们需要完整保留以判断"是否有响应"）
    for rec in (sources.get("progress") or []):
        day = normalize_date_to_ymd(rec.get("event_time") or rec.get("病历标题时间"))
        if day:
            day_map[day]["病程记录"].append({
                "病程时间": _as_text(rec.get("event_time") or rec.get("病历标题时间")),
                "病程名称": _as_text(rec.get("record_name") or rec.get("病历名称")),
                "病程内容": _as_text(rec.get("content") or rec.get("病历文书_内容")),
            })

    for rec in (sources.get("nursing") or []):
        day = normalize_date_to_ymd(rec.get("event_time") or rec.get("EVENT_TIME"))
        if day:
            day_map[day]["护理记录"].append({
                "护理时间": _as_text(rec.get("event_time") or rec.get("EVENT_TIME")),
                "护理单类型": _as_text(rec.get("record_name") or rec.get("护理单类型")),
                "护理内容": _as_text(rec.get("content") or rec.get("病情观察及护理措施")),
            })

    # 过滤掉既无异常检验、又无检查、又无病程、又无护理的空天
    return [
        {"日期": day, **group}
        for day, group in sorted(day_map.items())
        if group["检验报告信息"] or group["检查报告"] or group["病程记录"] or group["护理记录"]
    ]
```

### 改动要点

1. lab 只保留 `is_abnormal=true` 的记录（用已有的 `_is_abnormal_truthy` 函数）
2. exam 保持不变（检查报告数量通常少，且"异常"判断依赖描述文本而非标记）
3. progress 和 nursing 保持不变（需要完整保留以判断"是否有响应"）
4. 过滤掉完全空的日期（无检验、无检查、无病程、无护理）

### 预期效果

- mr_text 体积减少约 30-50%（去掉正常检验项）
- 减少无关天数（只有护理但无异常检验的天数被过滤）
- AI 判断准确性不受影响（AI 关注的是异常项有无响应）

### 影响评估
- 只影响 `discharge_final` 模式的 `jyjc_vs_bcnursing`
- 不影响 `daily_increment` 模式（不走逐日列表）
- 不影响其他审计类型
- 历史记录不变（只影响新推送）

## P4：admission_vs_first_progress text_quality 65% 触发【需用户确认】

### 复核结论：不确定是否为问题，需用户决策

### 分析

**text_quality 维度**是 Dify workflow 的 AI 判断，不在后端代码中定义。该维度判断的是病历文本质量（格式规范性、描述完整性、书写质量），65% 触发可能有两种解释：

**解释 A：过严**
- Dify prompt 对文本质量的要求过高
- 医院病历文本质量普遍不达标是正常的（基层医院常见）
- 应降低该维度的严重度从 warn/medium 降为 info/low

**解释 B：合理**
- 病历文本质量确实普遍有问题（格式不规范、描述不完整）
- 65% 的触发率反映了真实情况
- 不应该降低标准

### 需要用户确认

这个问题的判断取决于：
1. text_quality 维度的触发标准是什么？（需要查看 Dify workflow prompt）
2. 医院是否认为 65% 的文本质量问题是合理的？
3. 是否希望降低该维度的权重或严重度？

**建议**：
- 如果用户认为过严 → 在 Dify workflow 的 prompt 中调整 text_quality 的判断标准
- 如果用户认为合理 → 不做改动
- **此问题不在代码层面，需要用户决定后操作 Dify 平台**
