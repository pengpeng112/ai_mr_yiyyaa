## 5. D 轨：数据库只读探索（逐源独立验收）

### D0（P0）调查工具与只读保护

文件：优先审查 `review/jhemr-fileverify-056/read_only_p0.py`（含 EXPLAIN INSERT，不直接当通用探索器）、`app/database.py`、`app/emr_vastbase_client.py`、`prearchive_service/prearchive/{config,collectors,paperless,his_base,store}.py`。如需新增可复用工具，使用 `scripts/explore_databases_readonly_20260925.py`，离线测试 `tests/test_database_readonly_explorer_20260925.py`；过程 SQL 放 review，不把凭据写进去。

要求：
- 不加载可能写默认配置的业务启动流程；直接读取必需配置键且不打印整个配置，不调用 init_db、迁移、scheduler、trial、backtest、同步、健康修复或外发入口。
- 工具只执行审查过的固定 SELECT 模板/系统元数据查询；不开放任意 SQL 参数；显式允许 session-only 的只读和超时设置。禁止 DML/DDL、CALL/EXEC、SELECT INTO、FOR UPDATE、序列 nextval、用户自定义函数、DB link/外部表和未知有副作用视图。标准只读事务不能替代 SQL 白名单。
- PostgreSQL/Vastbase：连接前设 default_transaction_read_only，查询前确认 transaction_read_only；驱动/版本支持时设置 statement_timeout/lock_timeout；MySQL：验证版本支持的只读事务与超时。Oracle：首条事务语句 SET TRANSACTION READ ONLY，采用驱动 call timeout；不使用会写 PLAN_TABLE 的 EXPLAIN PLAN。SQL Server 不把 ApplicationIntent=ReadOnly 当权限隔离，优先现有 SELECT-only 账号，审查查询模板/对象，设置查询及锁等待超时；无法证明目标和只读保护时停该源。
- SQLite：确认绝对路径已存在，以 URI mode=ro 连接，启用 query_only；生产活库不复制裸 db 忽略 WAL，不使用 immutable 假设；备份/快照制作若会产生生产写另批，必要时停该分支。
- 默认单源单连接、并发1、连接10秒、语句15秒、锁等待2秒（驱动不支持时须使用可验证取消方案，否则不跑未知大查询）；元数据分页100行、最多1000对象/源，超出写明未覆盖；不默认全表 count。每源最多20条已审查查询/轮、30分钟/轮，超预算记录检查点后续跑。
- 业务采样只在内存中处理已批准字段，最多100行，默认不读姓名/证件号/电话/正文/患者标识；访次关联只落汇总和缺失率，不落原始键。小样本统计可能重识别时不展示稀有分组。错误输出清理 DSN/口令/SQL 参数。
- 连接最终 rollback/close；ROLLBACK 不保证对所有误执行操作有补救，故必须执行前约束。查询失败不能自动执行修复。

## 9. 对“一次性完成”的执行建议与本计划自审

问题不在于希望连续执行，而在于将完成的含义混在一起：代码完成、门禁通过、部署成功、临床验收和源系统接通是不同阶段。把它们压成一次“全部完成”，容易把等待输入伪装成完成、把历史授权扩展到新目标，或因一个库阻塞全部工作。

建议一次明确完整目标与边界，让AI连续完成所有具备条件的包；每个小批独立验收/恢复，在检查点留下真实状态。只有业务选择、未知资源和新增授权向人提问，普通技术问题自行修复。定期审阅D6问题优先级，避免“顺便优化”无限扩大范围。
