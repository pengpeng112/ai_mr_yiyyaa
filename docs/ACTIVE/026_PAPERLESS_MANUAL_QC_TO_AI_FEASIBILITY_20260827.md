## 2. 高频扣分点分类（TOP25 评分项 + TOP20 说明，2026）

### 2.1 A 类：确定性规则（纯代码/SQL 可判，不依赖 AI）

| 扣分模式 | 实例（2026 频次） | 判定方式 |
|---|---|---|
| 文书缺失 | 无长期医嘱单 89 / 无临时医嘱单 78 / 无手术安全核查表 57+35 / 无手术护理单 41 / 无体温单 36 / 无会诊单 34 / 无入院记录 43 / 无出院记录 33 | 文书清单比对（结构化，零歧义） |

| 字段空项 | 首页过敏药物未填写 211 / 首页过敏药空项（青霉素）51 / 入院记录出生地空项 52 | 字段非空校验 |
| 格式/重复 | 出院记录出院诊断重复 85 / 去掉分页符 45 | 文本规范化校验 |

### 2.2 B 类：语义一致性（需 AI 判断，现有六类质控已部分覆盖）

| 扣分模式 | 实例（2026 频次） | 现有 AI 质控对应 |
|---|---|---|
| 跨文书日期矛盾 | 病程记录出院日期错误 107 / 出院记录手术日期错误 67 | `timeline_consistency` 维度（各类型均有） |
| 诊断一致性 | 出院诊断重复/矛盾、诊断依据错误 | `discharge_vs_frontpage` / `admission_vs_first_progress` |
| 患者身份属性错误 | 首程记录诊断依据男女错 62 | `patient_identity`（025 昝淑霞案例同类） |
| 首页手术信息 | 首二手术类型错误 69 | `syssvsscbc`（首页手术 vs 术后首程） |

### 2.3 C 类：主观/规范类（AI 可辅助但不宜自动扣分）

知情同意书内容完整性（758）、术语规范/页面整洁（429）、术前小结质量（312）、病例特点逻辑性（274）等——评分标准含人为主观裁量，AI 只宜做"提示级"输出供人工复核，不得自动定级。

## 3. 与现有 Med-Audit 架构的映射

```
人工评分项（T_MARK_ITEM，~92项/份）
   ├─ A类确定性规则 → 新增"终末缺陷规则"审计类型：纯代码/SQL 层（不调Dify，零推理成本）
   │     复用现有机制：audit_types[] 配置化SQL源 + data_source_loader + payload_composer
   │     输出：缺文书/超时限/空项/重复 → severity=low/medium（按024/025教训，默认不判high）
   ├─ B类语义规则  → 并入现有六类 Dify 一致性质控的维度与提示词（影子V2已具备事实闭环结构）
   └─ C类主观规则  → 提示级提醒（review_only/manual_review），不进入扣分
```

严重度映射建议：人工扣分 0.5 分 → low（blue）；1 分 → medium（yellow）；2 分及以上或涉及患者安全（错侧/错患者/过敏）→ 按现有 High Gate 走。**吸取 024/025 教训：CDB 类不得自动 high，高危仅限错侧/错患者/过敏/身份冲突。**

## 4. "医生提交病历时提醒"的三条路径

| 方案 | 机制 | 依赖 | 时效 | 建议 |
|---|---|---|---|---|
| A. 嵌入 JHEMR 提交流程 | 嘉和在文书提交/签名事件回调 Med-Audit API，返回检查结果弹窗 | 嘉和厂商改造，周期长 | 事中（秒级） | 终态目标，先谈接口 |
| B. 准实时轮询 + 现有推送链路 | Med-Audit 轮询 JHEMR `v_blws` 新提交文书（Vastbase 只读），触发轻量检查，经现有企业微信/前置机通道提醒医生 | 仅后端开发，无厂商依赖 | 准实时（分钟级） | **推荐首选**，复用 Relay 告警链路 |
| C. 维持 T+1 批量提前 | 出院当天调度即跑 A 类规则 | 无改造 | 事后 | 兜底方案 |

方案 B 的检查分层：A 类规则本地秒级完成即可推送；B 类语义检查按批调度（控制 Dify 成本），高危才推送。

## 5. 人工质控结果作为金标准回流（最有价值的副产品）

`t_mark_main/detail` 是**现成的人工标注结果集**（2026 年 41,709 份）：
- 回测 AI 规则命中率：对每份人工质控病历跑 AI 规则，对比扣分项，统计 precision / recall / false-high rate（025 提出的验收指标直接落地）；
- 高频人工扣分项（§2）定义规则优先级；
- 长尾说明（4,991 种）做聚类归并，持续补充规则库。

**注意**：回测属只读分析， patient 级明细不出无纸化库（sjzc 红线）。

## 7. 风险与红线

1. **不替代终末质控评分**：AI 输出是"缺陷提示"，不直接写回无纸化评分表（写 T_MARK_* 属生产写入，须专项批准）。
2. **高危泛化教训**（024/025）：A/B 类规则一律 low/medium 起步，high 仅限安全类且过 High Gate。
3. **隐私**：分析只在聚合层做；患者明细、病历原文不落地到本仓库。
4. **无纸化库只读**：本分析全部查询经 sjzc 受控连接器，单条 SELECT。

## 8. 结论

人工质控规则**可以且应该**纳入 AI 质控：8,200 条/年的扣分说明中，A 类确定性规则（缺失/时限/空项/重复，约占高频量一半）可零成本代码化并覆盖人工 60%+ 的流水核对工作；B 类并入现有六类语义质控；C 类保持提示级。`t_mark_*` 同时是现成的金标准，可闭环验证 AI 质控准确性——这是比"减负"更有长期价值的资产。
