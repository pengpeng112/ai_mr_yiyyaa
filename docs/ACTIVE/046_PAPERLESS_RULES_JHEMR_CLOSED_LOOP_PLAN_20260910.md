## 3. 目标架构和数据契约

### 3.1 延续双引擎、统一核查视图

- 原 AI 引擎：仍由主服务的配置/loader/payload/Dify/High Gate/PushLog/既有通知路径运行。
- 无纸化规则引擎：复用独立 prearchive_service 采集器、DSL、规则仓、结果仓和 Outbox，补齐运行接线。
- 主服务经受控 HTTP BFF 访问预检，提供统一核查工作台；不得相互 import 业务模块。
- 展示区分 `origin=ai|paperless_rule|system_report|manual_review`；同一问题可关联来源，不能覆盖原 AI 记录或合并后丢掉规则版本/证据。
- 本轮默认只向 JHEMR 投递新规则结果；原 AI 结果在核查视图关联显示。把原 AI 结果也外发 JHEMR 是额外范围，需明确选择，防止双发。
- 使用现有单进程约定。长任务独立队列/worker，BFF/API 不同步等待整批查库和 AI；故障隔离不等于把无法判断改成合格。

### 3.3 状态口径

- `pass`：适用且所需数据完整，已执行并满足该条款。
- `fail`：适用、数据充分，有明确违例证据。
- `unknown`：源故障、身份关联不确定、字段不可用、事件/文书时间无法可靠取值。
- `not_applicable`：有可靠证据证明该就诊/事件不适用；不能把“没采到手术”自动等价于无手术。
- `pending`：尚未到检查期限或等待明确的数据到达；应安排复查时间。
- disabled/dept_excluded 作为执行范围排除原因登记，不计已通过。

汇总至少给出：目录数、适用数、实际执行数、通过数、缺陷数、unknown数、pending数、排除数、数据覆盖率。全 unknown/全排除/零规则不得显示“全部通过”。外部 JSON 现有 v1 不足时采用兼容版本协商（优先 v2 新契约），不能在 v1 静默改变字段语义；v1 目标不支持的状态须显式转换/拒投并标原因。

## 4. 人工规则提取与覆盖方案

### 4.1 92 条全部进入台账，不承诺 92 条全部自动判定

T1 从现有 92 项快照生成机器可读 `prearchive_service/rules/paperless_coverage_v1.json`，每 FID 一条主记录，再关联原子规则。已有 030 分组计数可作历史对照，不作为新分类永远不变的裁决。

每条包含：原文及 hash、规则解释、原子条款、判定方式 deterministic/ai_assist/manual/data_blocked、执行 rule_id、实际覆盖子句、未覆盖子句、数据字段/来源、业务阈值出处、正反例、严重度、参考分、启用状态、负责人/下一步。不得仅写“A/B/C”。

目录提取与发布分开：确定性解析与本地预填可直接完成；AI 可辅助生成草稿，但不自动发布、不自动配置新临床阈值、不把原文或患者资料交给未经批准的外部模型。原始快照永久保留，新目录变更有新增/停用/改名/改分/改组/消失项差异；消失项不能在未核对源查询范围时当停用。

### 4.1.1 AI自动匹配是本期必做功能

不是要求用户手工填写92条，也不是只在文档里给建议。提供“一键匹配全部/选中项→查看候选→批量试运行→观察→选中确认发布”流程。

- 输入：评分项原文、已确认阈值、已发布/候选DSL、已验证字段注册表和来源说明；不包含患者病历、姓名等。只用院内已批准的模型通道，独立配置和预算，不改原患者质控工作流。
- 先精确匹配FID/原文hash/已有规则，再由模型对余项给候选；已确认映射不被重新生成覆盖。
- 模型输出受JSON Schema约束：FID、原子条款、matched_rule_ids、suggested_dsl、field_refs、covered_clauses、uncovered_clauses、rationale、confidence、blocking_reasons、建议正反例。每个字段引用必须能在能力注册表解析。
- 确定性校验器校验FID、字段、来源、事件、阈值出处、DSL类型、禁用任意代码/SQL；不存在字段或臆造阈值进入blocked，不能因高confidence绕过。
- 持久化匹配任务、model/prompt版本、输入hash、结果、用户接受/驳回/修改；分批、可取消、限时重试、断点恢复；相同输入复用结果，费用/耗时可查。
- 对C类、模糊条款照样给最接近能力和不能自动化的具体原因；不得为了“92条匹配率”把所有条款塞进泛化LLM检查。
- 本地执行使用可控模型stub验证完整流程；院内模型通道配置后同一路径真实匹配。没有可用模型凭据时交付可运行的匹配worker/API/界面/适配器和明确配置项，不冒称已做真实AI匹配。
- 用户可直接把通过结构校验的候选批量加入独立trial规则集；trial允许执行、保留结果及人工反馈，但不改正式发布指针、不触发扣分/阻断或正式外发。
- 观察页展示每条规则的执行量、命中、unknown、用户确认缺陷/误报/待核实、模型建议与人工修改差异；用户确认后才进入正式版本。规则生成模型输出不直接作为患者缺陷。

### 5.1 源能力登记

### 5.2 双层触发

1. 过渡：保持显式配置 `paperless_rpa` 增量采集完成检查，页面显示“采集完成后检查”，不宣传即时提醒。

3. 医生查看/点击重新检查可以创建异步任务；禁止在UI线程阻塞等待完整采集。
4. 期限内 pending、迟到报告、整改后文书更新必须可重检，即使完成锚点不变也可生成新的 run revision；轮询旧检查键去重不能把复检永久抑制。
5. 同秒超批使用稳定复合游标；失败就诊可重试，不能推进水位后永久跳过失败项；固定批量上限、超时和 backpressure。
