# 前端混合风格界面大改计划

## 1. 改造目标

本计划用于指导 AI 或开发者对 med-audit 前端进行系统性界面大改。目标不是零散美化，而是把当前系统改造成“日常业务页面清晰高效，首页与流程页具备科技驾驶舱感”的医疗质控后台。

最终风格选择：混合风格。

- 首页总览、运行总览、推送链路、系统健康：采用深色科技驾驶舱风格，突出实时状态、风险趋势、链路健康。
- 患者质控、推送日志、质控反馈、前置机告警、配置中心：采用浅色医疗后台风格，强调高密度信息、清晰筛选、稳定可读。
- 详情页、弹窗、抽屉：采用左右分栏、证据链、时间线布局，帮助质控员快速判断“问题是什么、证据在哪里、下一步做什么”。

## 2. 设计技能来源与执行约束

本计划生成时参考了以下医疗后台设计 skills。由于后续执行者可能无法访问这些 skills，本节直接内联关键约束，执行时以本文档为准。

- `medical-ui-design-system`：统一医疗后台视觉系统、颜色、间距、卡片、按钮、表单、状态标签。
- `medical-dashboard-screen`：首页总览、驾驶舱、ECharts、KPI、风险趋势、系统健康。
- `medical-table-experience`：患者质控、推送日志、反馈、告警、审计类型等表格页体验。
- `medical-detail-redesign`：日志详情、患者详情、AI 结果详情、反馈详情、证据链与时间线。
- `medical-workflow-visualization`：调度、Dify 推送、多目标负载均衡、前置机推送、闭环流程可视化。

必须内联遵守的核心约束：

- 当前系统是静态 Vue + Element Plus + ECharts，不引入 Tailwind、GSAP、Framer、Three 或完整构建链。
- 优先修改 `static/styles/`、`static/templates/pages/`、`static/scripts/modules/`，不要为了视觉重写后端接口。
- 浅色业务页保持医疗后台风格：可信、清晰、稳重、低噪声。
- 深色驾驶舱只用于首页、运行总览、健康态势、流程态势等局部容器，不扩散到所有表格页。
- 表格页必须包含摘要、筛选、工具栏、表格、分页、加载、空状态、错误状态。
- 详情页必须突出风险等级、问题摘要、证据摘录、整改状态、闭环时间线。
- 工作流页面必须展示失败原因、跳过原因、下一步入口，不隐藏异常状态。

## 3. 项目技术约束

当前项目不是现代构建链 SPA，而是静态 Vue + Element Plus + ECharts。

- 调度、推送、Dify、多目标、前置机告警属于回归敏感链路，只改展示，不改执行语义。

## 4. 总体视觉方向

### 4.1 视觉关键词

- 医疗可信
- 风险清晰
- 数据密集但不拥挤
- 深浅分区明确
- 异常优先
- 流程可解释

### 4.2 全局浅色 Token

当前 `static/styles/app.css` 已经存在一套正式 token，位于 `:root`，包括 `--color-*`、`--surface-*`、`--text-*`、`--compact-*`。阶段 1 不允许另起一套独立配色体系。正确做法是收敛现有 token，并把新增语义 token 映射到现有 token。

现有基线：

```css
:root {
  --color-primary:  #1677ff;
  --color-success:  #52c41a;
  --color-warning:  #fa8c16;
  --color-danger:   #ff4d4f;
  --color-info:     #8c8c8c;
  --surface-page:   #f3f6fa;
  --surface-card:   #ffffff;
  --text-primary:   #262626;
  --text-secondary: #595959;
  --text-tertiary:  #8c8c8c;
  --card-radius:    8px;
  --card-shadow:    0 1px 3px rgba(15,23,42,.06);
}
```

允许补充的别名必须引用现有 token，不能直接使用另一套 Tailwind 风格蓝红配色。

```css
:root {
  --ui-bg: var(--surface-page);
  --ui-surface: var(--surface-card);
  --ui-surface-soft: #f8fafc;
  --ui-border: var(--border-subtle);
  --ui-text: var(--text-primary);
  --ui-text-muted: var(--text-secondary);
  --ui-primary: var(--color-primary);
  --ui-danger: var(--color-danger);
  --ui-warning: var(--color-warning);
  --ui-success: var(--color-success);
  --ui-info: var(--color-info);
  --ui-radius-sm: var(--card-radius);
  --ui-radius-md: 10px;
  --ui-radius-lg: 14px;
  --ui-shadow-card: var(--card-shadow);
  --ui-shadow-soft: 0 6px 18px rgba(15,23,42,.06);
}
```

执行要求：

- 以 `--color-*` 为颜色唯一来源。
- `--ui-*` 只作为语义别名，禁止独立硬编码另一套主色、危险色、成功色。
- Element Plus 组件色彩如需统一，优先映射到 `--el-color-primary` 等变量，但必须与 `--color-primary` 保持一致。
- 每次替换页面硬编码时，先查是否已有对应 token，避免新增重复变量。

### 4.3 驾驶舱深色 Token

用于首页、运行总览、系统健康、流程态势页的局部容器，不应污染所有页面。

```css
.theme-cockpit {
  --dash-bg: #07111f;
  --dash-panel: rgba(15, 23, 42, 0.86);
  --dash-panel-soft: rgba(30, 41, 59, 0.72);
  --dash-border: rgba(148, 163, 184, 0.18);
  --dash-text: #e5edf7;
  --dash-muted: #8fa3bf;
  --dash-primary: #38bdf8;
  --dash-success: #22c55e;
  --dash-warning: #f59e0b;
  --dash-danger: #ef4444;
  --dash-glow: 0 18px 60px rgba(8, 47, 73, 0.36);
}
```

### 4.4 状态颜色统一

状态色不得随页面变化。

- 高危、失败、解析错误：红色 `danger`
- 中危、待处理、跳过但可解释：橙色 `warning`
- 成功、已闭环、已推送：绿色 `success`
- 运行中、信息、低危：蓝色 `info`
- 不适用、无数据、历史缺失：灰色 `muted`

## 5. 信息架构重组

当前导航分组已经包含：工作台、质控业务、推送管理、配置中心、运维管理。建议保留分组，但优化视觉层级和页面职责。

### 5.1 工作台

- 首页总览：深色驾驶舱，回答“今天系统是否正常、风险集中在哪里、下一步看哪里”。

### 5.2 质控业务

- 患者质控：按患者/科室/风险维度管理问题。
- 前置机告警：查看告警发送、失败、医生触达状态。
- 质控反馈：查看医生反馈、整改闭环。
- 推送日志：查看 AI 推送原始记录、结果、重推、导出。

### 5.3 推送管理

- 手动推送：用任务向导/步骤式布局降低误操作。
- 定时任务：显示调度策略、运行模式、下次执行、最近结果。
- 推送进度：显示批量任务实时进度、成功/失败/跳过原因。

### 5.4 配置中心

- 系统配置：按数据源、Dify、推送参数、通知等分区。
- 审计类型：突出启用状态、数据源、Dify 目标、SQL 风险。
- 企业微信推送配置：保留现有配置能力，提升分组和预览。
- 运行总览：只读诊断页，建议做成半驾驶舱 + 配置风险列表。

### 5.5 运维管理

- 系统健康：深色或半深色健康面板。
- Dify 调试：技术调试页，必须明确输入、输出、解析状态。
- 权限管理：浅色表格/树形权限。
- Oracle 连接、运行日志：运维信息密集页。

## 阶段 1：全局视觉系统重建

目标：统一整体产品质感，解决“每个页面像不同系统”的问题。

优先文件：

- `static/styles/app.css`
- `static/styles/components/header.css`
- `static/styles/components/sidebar.css`

- `static/styles/components/table.css`，如不存在则新增

执行任务：

- 收敛现有全局 CSS token，包括颜色、圆角、阴影、间距、字体、状态色；禁止新增与 `--color-*` 冲突的独立主色体系。
- 如确需新增 `--ui-*`，必须作为 `--color-*`、`--surface-*`、`--text-*` 的别名或补充语义变量。
- 将 `body` 背景统一为浅灰蓝医疗后台底色。
- 将 `#app` 从固定 `height:100vh` 逐步改为兼容 `100dvh` 的布局，避免移动端地址栏问题。
- 统一 `.page-card`、`.sub-card`、`.card-title`、`.action-row`、`.table-container`、`.config-hint` 等基础类。

- 优化侧边栏和顶部栏，减少图标噪声，当前 `navigation.js` 中大量 emoji 后续建议替换为 CSS 图标块或 Element Plus 图标名。

设计要求：

- 浅色页面卡片层级最多三层：页面背景、主卡片、局部重点卡。
- 所有主内容区默认 `padding: 16px 20px`，1366px 下不拥挤。
- 表格页密度偏高，但筛选区要有清晰分组。
- 不使用霓虹高饱和渐变，不使用纯黑背景。

验收标准：

- 首页之外的业务页视觉统一。
- 表格 hover、按钮、标签、卡片标题一致。
- 1366px 下无横向溢出，768px 下内容可折叠。
- `rg "#[0-9a-fA-F]{6}" static/styles/pages static/styles/components` 检查新增硬编码颜色，确认必要且没有重复 token。

患者质控页重点：

- 顶部摘要增加：高危患者数、待整改数、今日新增、闭环率。

验收标准：

- 空数据、加载中、接口失败都可读。

强制规则：

- 修改已有 CSS/JS 后，必须递增 `static/index.html` 中对应资源的 `?v=` 参数，避免浏览器缓存导致测试看到旧样式。

## 10. 交互与文案规范

按钮文案：

- 使用“开始推送”“执行预检”“保存配置”“重新检测”“导出 CSV”“查看详情”。

错误状态：
