# AI 协作规则（多 AI 记账、落位与交接操作细则）

> **适用范围**：本仓库所有 AI 代理（ZCode / Codex / Claude / Antigravity 及各类模型）与人类开发者。
> **规则层级**：本节与 `AGENTS.md`「多 AI 协作启动与留痕协议」节语义一致，两文件互指；核心原则、生产/Git/PHI 授权红线以 [AGENTS.md](../AGENTS.md) 为唯一权威，本文件只规定操作细则，不重复复制红线正文。冲突时以 `AGENTS.md` 为准并立即报告。

---

## 1. 会话启动与现场保护细则

1. 按 [开发起步包/README.md](README.md) §1 完成 4 步启动，读 [01_统一修改记录.md](01_统一修改记录.md) **最后 10 行**与 [02_协作任务板.md](02_协作任务板.md)。
2. 动文件前执行 `git status --short`、`git diff --stat` 核对工作区已有改动。
3. **未登记改动处置（防误停工、防误覆盖）**：
   - 发现与当前任务**无文件重叠、无代码依赖**的未登记变更：保留原状继续执行当前任务，交付时附带提示即可，不必中途停工打断用户。
   - 仅当当前任务**需要修改或依赖归属不明的脏文件**时，暂停涉及冲突的部分，报告具体文件与差异请用户裁定，同时继续不依赖冲突的工作。
   - 严禁覆盖、回滚他人改动，也不得伪造上一任授权或代写未经核实的事实。
4. 工具与模型分别署名（如 `Antigravity / Gemini`、`ZCode / GLM-5.3`、`Codex / GPT`），未知版本如实写未知。通用交接模板见 [119 多 AI 协作指南](../docs/reference/119_MULTI_AI_COLLABORATION_GUIDE.md)。

## 2. 统一修改记录制度（强制）

任何会话只要**修改了仓库内任何文件**（代码/文档/配置/脚本的增删改移）或**对生产环境执行了写入/状态变更**，结束前必须在 [01_统一修改记录.md](01_统一修改记录.md) 表格末尾追加一行（仅只读核查默认在答复中报告范围与结论，专项审计明确要求留档时按其规定登记）。

| 字段 | 要求 |
| :--- | :--- |
| 日期 | `YYYY-MM-DD`（跨天写起止） |
| 执行者 | `工具 / 模型` 或人名 |
| 类型 | `代码` / `文档` / `数据整改` / `生产部署` / `目录整理` / `复核` / `交接` 之一 |
| 摘要 | 1–2 句说清做了什么，涉及数量/测试/释放体积须给真实数字 |
| 影响范围 | 关键文件路径或表名；多文件写核心目录并指明详细报告路径 |
| 生产写入 | `无` / `有`（有则写明授权来源、备份位置与回滚点） |
| 证据 | 文档编号、验证命令与退出码、commit hash 或 `review/` 报告路径 |

补充约定：
- **严禁改写历史行（append-only）**；发现历史行错误时新增更正行。当台账体积过大（如超过 200 行或跨季度/大阶段）时，经用户批准可将早期段落**原字节封卷**至 `docs/archive/changelog-<起止>/` 并在现行 `01` 文首留指针。
- 长任务每完成一个可复核批次即更新检查点并追加记录；获准 Git 提交后新增关联登记行补记 commit hash（补记行默认留在工作区说明，不递归提交）。

## 3. 资产落位规则（散文件治理）

| 资产类型 | 唯一允许位置 | 命名规范 |
| :--- | :--- | :--- |
| 现役运维 / 整改 / 生成脚本 | `scripts/`（历史一次性脚本归 `scripts/archive/`） | `*_YYYYMMDD.py`（日期后缀强制） |
| 现役计划 / 交接 / 复核文档 | `docs/ACTIVE/` | `NNN_描述_YYYYMMDD.md`（编号向 `docs/INDEX.md` 取下一个） |
| 长期契约 / 规范 / 基线 / 编年史 | `docs/reference/` | 沿用 `101+` 连续编号 |
| 整改证据 / 备份 JSON | `docs/remediation/` | `*_YYYYMMDD.json` |
| 截图、导出附件（含 PHI） | `docs/attachments/` | `描述-YYYYMMDD/` 目录包裹；**禁进 Git、禁外发** |
| 已完成/过时资产归档 | `docs/archive/` | `<主题-YYYYMMDD>/` 包裹 + `README.md`（编号计划附 `archive-manifest.json`） |
| 过程检查点 / 门禁日志 / 交付报告 | `review/<任务ID>/` | 不入 Git；长期结论升格至 `docs/` 或 `01` |
| 根目录 | 仅允许仓库级说明（`AGENTS/CLAUDE/ARCHITECTURE/DEPLOY/CODE_STYLE/README_CN`）与部署必需文件 | 新增须同步更新 `开发起步包/README.md` §3 |

> 任何 `docs/**/*.md` 的新增、重命名、移动、归档或删除，**同一变更内**必须同步更新 `docs/INDEX.md` 并运行 `python scripts/check_documentation_20261002.py`（检查器会自动拦截根目录与 `docs/` 顶层的未规范散落 Markdown）。

### 3.1 用户新建文书主动整理与规范化规程（所有 AI 必遵）

用户经常会在根目录、`docs/` 顶层或 `开发起步包/` 随手新建需求说明、升级文书、会议纪要、Excel 或截图。后续任何 AI 接手时，按以下规则主动协助整理：

| 用户新建/放入的内容 | AI 规范化动作 | 保护与禁忌 |
| :--- | :--- | :--- |
| 新需求、改造计划、升级说明、交接/复核 `.md` | 取 `docs/INDEX.md` 下一三位编号，规范命名为 `docs/ACTIVE/NNN_中文或英文主题_YYYYMMDD.md`，补齐文首「建立日期/定位/授权边界」元信息并同步登记 `docs/INDEX.md` | 不改写用户核心业务语义；已完结后再按阶段归入 `docs/archive/` |
| 长期接口规范、数据契约、操作手册 `.md` | 取 `1XX` 连续编号落位 `docs/reference/1XX_主题_YYYYMMDD.md`，同步登记 `docs/INDEX.md` | 避免与 `101`–`124` 已有契约重复建两份，优先增量更新现役契约 |
| 历史升级记录、已完成旧说明 `.md` | 原字节迁入 `docs/archive/<主题-YYYYMMDD>/` 并更新该目录 `README.md` 与 `docs/INDEX.md` | **只归档不删除**，完整保留系统升级历史见证 |
| Excel、Word、PDF、截图、导出表 | 移入 `docs/attachments/<主题-YYYYMMDD>/`（若含用户明确留置的根目录 `user*.xlsx` 除外） | 先判断是否可能含患者隐私（PHI）；`docs/attachments/` 已入 `.gitignore`，**严禁提交 Git、严禁外发或贴入正文** |
| 一次性脚本 / 临时压缩包 | 有效脚本加 `_YYYYMMDD` 后缀归入 `scripts/`；用完的临时 `.tar.gz`/`.zip` 提示确认后清理 | 不误删 `oracle-client/`、测试硬依赖 `.bak` 或其他 AI 未提交在研代码 |

> **执行时机**：任务明确围绕该文书展开时，AI 直接规范归位并在 `01_统一修改记录.md` 留痕；在其他任务中顺带发现用户新放的散落文件时，先保留原位不打乱，并在答复末尾简明列出归位建议待确认。

## 4. 生产写入留痕与专项批准口径

生产写入授权总边界见 `AGENTS.md` §2。执行已获批的生产变更时必须满足 5 步留痕：
1. 核对当次书面授权覆盖具体动作、范围与条件；
2. 写前备份（数据整改先出 dry-run JSON 落 `docs/remediation/`，容器热更先打回滚镜像 tag + tar 备份）；
3. 明确回滚点与回滚命令；
4. 写后只读 verify 并将实测结果记入 `01_统一修改记录.md`；
5. 容器热更 `.py` 后清 `__pycache__/` 并 `docker commit` 持久化。

> **专项高危审批单口径**：仅针对**生产批量推送、历史 high 降级/补跑、生产 DDL/DML、全院默认入口切换**等高冲击变更，需提供完整要素（环境、类型、日期/科室、数量、`alert_policy`、接收人、before hash、回滚点；参考 `docs/ACTIVE/023` §9.1，024/025 不授权清单持续有效）。普通已明确动作与范围的单点变更按 `AGENTS.md` §2 执行，不强套九字段审批表。

## 5. 并发分工、交接与 Git 细则

- **串行接力 vs 并行多开**：
  - **串行接力（常态，单会话工作）**：当前 AI 直接更新 `02_协作任务板.md`、追加 `01_统一修改记录.md` 与同步 `docs/INDEX.md`。
  - **并行多开（仅当用户明确同时派出多个 AI 改同一工作区）**：由用户或约定的一位主协调 AI 统一写共享导航/`INDEX`/`01`/`02`，其余执行 AI 在各自 `review/<任务ID>/DELIVERY.md` 中输出待登记行，业务文件范围互不重叠。
- **任务板轻量化维护**：`02_协作任务板.md` 仅保留 `RUNNING`/`HANDOFF`/`BLOCKED` 及最近 5 条 `DONE`，超过 10 条 `DONE` 时将最旧行归档至 `docs/archive/taskboard-*`。
- **Git 提交归属核对**：用户未明确要求时不提交；获准提交且工作区混有多 AI 改动时，逐文件对照 `01` 核对归属，严禁打包他人半成品。提交信息格式：`类型(范围): 中文摘要`。未获提交授权时，完成实现、验证、文档与登记后以「本地交付完成，未提交」交付。
- **本规则修订**：须经用户批准并在 `01_统一修改记录.md` 登记。
