# Med-Audit 一次性执行交付规程

## 1. 全流程（十步，按序）

1. **会话启动 4 步**：按 `AGENTS.md` §3 读取 `AGENTS.md` → `开发起步包/README.md` & `00_AI协作规则.md` → `01_统一修改记录.md` 末 10 行 & `02_协作任务板.md` → `docs/INDEX.md`。
2. **读 PROMPT**：读取当前任务 PROMPT（如 `开发起步包/prompts-064/PROMPT-00` + `PROMPT-WPxx`，或 `开发起步包/PROMPT-*.md`；历史 PROMPT 在 `docs/archive/`），认清版本号与代码事实基线；若提示词与真实代码冲突，一律以真实代码为准并在偏差说明中登记。
3. **读作业书**（如 `docs/ACTIVE/064_*.md` 或任务指定计划）：认清已裁定业务口径（不再争论）、红线与文件白名单。
4. **冻结基线**：记录 `git status --porcelain` + `HEAD`；完整保留工作区既有他人未提交改动，严禁 `reset`/`clean`/`stash`。
5. **逐包执行**：按顺序完成子任务并跑本包定向验收测试；验收失败时暂停依赖该结果的后续包，定位根因并在授权范围与白名单内修复重跑；连续 3 次同类失败无新证据立即停止并报阻塞。改变业务裁定或降低验收标准须走升级出口。
6. **checkpoint**：每完成一包/阶段写检查点（如 `review/064-wpNN/exec-log.md` 或 `review/exec-log.md`，不入库），支持跨会话断点续跑。
7. **验证门禁**：单包交付按 PROMPT 要求执行定向测试 + `run_gates_20260906.py --quick`；总交付或明确要求全绿时执行 `--full --anchor-file docs/reference/gate_anchors.json`（见 `med-audit-gates` skill），不得削弱断言或私自下调锚。
8. **交付报告**：优先使用当前作业书/PROMPT 指定的路径（如 `review/064-wpNN/DELIVERY.md`）；若作业书明确要求正式编号报告则取 `INDEX` 可用编号，已有对应报告则更新，不新建重复报告。内容覆盖改动清单、验证数字、偏差说明、未完成项与回滚方案。
9. **登记**：追加 `开发起步包/01_统一修改记录.md` 一行、更新 `02_协作任务板.md`；如增删移动 `docs/**/*.md` 同步更新 `docs/INDEX.md` 并跑通 `check_documentation_20261002.py`；仅当当前作业书明确要求回写特定母文档时同步更新。
10. **按已有授权收尾**：`commit/tag/push/PR` 分别核对当次授权，已覆盖范围不重复询问；旧计划批准不构成常设授权。无提交授权时以「本地交付完成，未提交」收尾；获准提交后在 `01` 追加关联行补记 hash。

## 2. 硬性纪律（违反=交付作废）

- 作业书"已裁定（禁止再争论）"节针对**业务裁定**不再重新论证，直接执行；环境、路径、计数等**事实性陈述**仍须按证据核验，发现不符时按偏差说明登记并修正执行依据，不改变业务裁定本身。
- 禁止为凑绿削弱有效断言或删除必要覆盖；获批行为变更可同步更新相关测试，并说明覆盖变化。
- 历史文档数字/正文不改写（append-only）；历史状态按文档状态判定，不按文件名是否带日期判定，现役文档可按任务更新；docs/**.md 增删移动必须同步 INDEX。
- PHI 不进产物；引用会话导出只写文件名+小节号。
- 升级出口：仅在需要扩大授权范围或文件白名单、修改业务裁定、降低验收标准、执行未批准生产动作时，暂停对应工作并问用户。删除文件、仅做指针化等限制仅在当前作业书明确规定时适用；作业书的非语义笔误可依据代码和明确契约修正并记录，不得借此改变验收口径。
