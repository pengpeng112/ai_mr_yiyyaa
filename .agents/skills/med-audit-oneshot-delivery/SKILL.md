# Med-Audit 一次性执行交付规程

## 1. 全流程（十步，按序）

1. **会话启动五步**：`AGENTS.md` → `开发起步包/README.md` → `00_AI协作规则.md` → `01_统一修改记录.md` 末 10 行 → `docs/INDEX.md`。
2. **读 PROMPT**（`开发起步包/PROMPT-*.md`）全文，认作业书版本号（v1.0/v1.1 以 PROMPT 声明为准；INDEX 现役作业书已有更新版本、或用户在当前任务中明确修订时，以最新版本为准并在偏差说明中记录来源）。
3. **读作业书**（`docs/ACTIVE/NNN_*.md`）全文，认 §0 修订记录、已裁定事实（禁止再争论项）、红线与白名单（允许/禁止修改文件清单）。
4. **冻结基线**：记录 `git status --porcelain` + HEAD；工作区若有上一任未提交改动，全部保留，禁止 reset/clean/stash。
5. **逐包执行 T0-Tn**：按作业书顺序，每包做完立即跑该包验收测试；验收失败时暂停依赖该结果的后续包，先定位原因；在已授权范围和白名单内修复代码、环境或脚本并重跑，继续不依赖失败结果的工作。改变业务裁定或降低验收标准须走升级出口。
6. **checkpoint**：每包完成写 `review/exec-log.md`（不入库；格式=T0-Tn 逐包一行事实+测试数字），支持跨会话断点续跑。
7. **全绿门禁**：`python scripts/run_gates_20260906.py --full`（见 `med-audit-gates` skill）；当前回归锚以 `docs/reference/gate_anchors.json` 为准（需比锚时显式传 `--anchor-file`）；专项作业书可增加明确要求。数量下降须核查覆盖，不得自动下调锚掩盖失败；改变既定验收标准仍需批准。
8. **交付报告**：优先使用作业书明确预留的路径；未预留时取 INDEX 可用编号，已有对应报告则更新，不新建重复报告。结构参考 042 §1-§10，只保留适用章节（逐包勾选表/门禁表/用户怎么点开/契约变化/偏差说明/未做清单/回滚/INDEX+01 登记证明）；文件名以作业书钉死为准。
9. **登记**：`docs/INDEX.md`（作业书仅在实际完成后标已执行 + 新增或更新对应交付报告行 + 盘点行前缀）+ `开发起步包/01_统一修改记录.md` 追加一行（字段见 00 规则 §2；带证据路径）；作业书要求的母文档追加行（如 023 §0.6）同变更内完成。
10. **按已有授权收尾**：commit/tag/push/PR 分别核对当前任务授权，已覆盖范围不重复询问；旧计划批准不构成常设授权。无提交授权则完成其余交付并报告“本地交付完成，未提交”；获准提交后新增 01 关联登记行补记 hash。

## 2. 硬性纪律（违反=交付作废）

- 作业书"已裁定（禁止再争论）"节针对**业务裁定**不再重新论证，直接执行；环境、路径、计数等**事实性陈述**仍须按证据核验，发现不符时按偏差说明登记并修正执行依据，不改变业务裁定本身。
- 禁止为凑绿削弱有效断言或删除必要覆盖；获批行为变更可同步更新相关测试，并说明覆盖变化。
- 历史文档数字/正文不改写（append-only）；历史状态按文档状态判定，不按文件名是否带日期判定，现役文档可按任务更新；docs/**.md 增删移动必须同步 INDEX。
- PHI 不进产物；引用会话导出只写文件名+小节号。
- 升级出口：仅在需要扩大授权范围或文件白名单、修改业务裁定、降低验收标准、执行未批准生产动作时，暂停对应工作并问用户。删除文件、仅做指针化等限制仅在当前作业书明确规定时适用；作业书的非语义笔误可依据代码和明确契约修正并记录，不得借此改变验收口径。
